# 우리길(WONWAY) 프론트엔드 MVP

고객의 일상 언어로 은행 업무를 안내하는 React + TypeScript + Vite 해커톤 프로토타입입니다. **우리은행 공식 서비스가 아니며, 실제 금융거래·상담 연결·예약은 실행하지 않습니다.**

## 실행

검증 환경: Windows / Node.js 24.20.0 / npm 11.19.0. Node 24 사용을 권장합니다.

```sh
npm ci
npm run dev -- --port 5173
```

실행 주소: http://127.0.0.1:5173/ (포트 사용 중이면 Vite 출력 주소 확인).

```sh
npm run typecheck
npm run lint
npm test
npm run build
```

프로덕션 산출물은 `dist/`에 생성됩니다. 개발 서버는 정식 배포가 아닙니다.

## 화면과 가상 시연

홈 → 고객센터 문의 입력 후, 추가 질문이 필요하면 **채팅에서 같은 세션으로 문답**합니다. 추천이 완료되면 **별도 AI 추천 결과** → **AI로 해결하기 / 답변 확인하기** → 같은 세션의 채팅 → 서버가 제공한 업무 목업 메뉴 → 상담 복귀 순서입니다. 정보가 이미 충분하면 추가 질문 없이 추천 화면으로 이동합니다. 홈 계좌와 업무 내역은 시연용이며 실제 계좌 API를 호출하지 않습니다.

첫 문의 전송 후 실제 요청이 진행되는 동안 별도 분석 화면에 “어떤 상담이 필요한지 확인하고 있어요.”를 표시합니다. 보라색 심볼·점 표시·안내 문구로 구성하며 인위적인 지연은 추가하지 않습니다. 오류 시 입력을 유지한 문의 화면으로 돌아가고, 대화 중 후속 요청은 기존 채팅의 로딩 표시를 사용합니다. 분석 중 홈으로 이동하면 늦은 응답으로 화면을 강제로 전환하지 않습니다.

추천 결과에는 짧은 목적 요약, 추천 채널과 이유, 채널 선택 버튼을 표시합니다. 서버의 `consultationSummary`는 목적만, `guidance`는 공식 정책에 근거한 상세 업무 안내만 담습니다. 상세 안내는 채널 선택 뒤에 표시합니다. CHATBOT / PHONE / EMAIL은 챗봇·전화·이메일 상담으로 표시하고 API 응답 순서를 유지합니다. `rank`가 있으면 서버 순위(동점 포함)를 그대로 표시하며, 이전 서버에서 순위가 없으면 응답 목록 순서로 표시합니다.

추천이 있으면 1·2·3순위 영역을 모두 표시합니다. 서버가 세 개보다 적게 반환하면 나머지 영역에는 ‘추천 없음’ 비활성 카드를 표시하며 임의의 채널이나 추천 근거를 만들지 않습니다. 추천 목록은 접지 않고 모두 표시합니다. 첫 채널은 파란 카드와 활성 버튼으로 강조하고, 나머지는 회색 참고 카드와 비활성 버튼으로 표시합니다. 업무 목업 버튼은 CHATBOT을 선택하고 서버가 해당 메뉴를 제공한 경우에만 표시합니다. 선택 후 업무 카드는 짧은 목적 요약과 메뉴 버튼만 보여주고 긴 정책 본문과 중복 요약 영역은 표시하지 않습니다. 실제 조회·변경 없음 표시는 유지합니다.

문의 입력 화면의 빠른 도움말은 기존 박스를 유지합니다. 채팅 화면에서만 답변·업무 안내 뒤에 “빠른 도움말도 볼까요?” 후속 버튼을 표시하며, 누르면 같은 스크롤 영역에서 FAQ / 안내·지원을 펼칩니다. 승인된 컬러 시안에 맞춰 고객 메시지·문의 요약은 연한 회색, AI 말풍선은 하늘색, 추천·업무 카드는 파랑, 카드 안의 이동 버튼은 흰색으로 구분합니다. 입력 시 민감정보 주의사항과 업무 화면 확인 안내는 노란 TIP 영역으로 표시합니다. 파란 배경은 흰 글자의 가독성을 위해 시안보다 약간 어둡게 조정했습니다.

기본 모드는 mock입니다. AI가 실제로 판단하지 않습니다. 아래 예시 버튼은 입력창만 채우며 고객이 전송해야 합니다. 정해진 예시의 공백·문장부호 차이만 허용합니다.

### 자동이체

1. 홈의 **우리길 AI 고객센터**를 누릅니다.
2. **생활비 보내는 날짜 바꾸기** 예시를 입력합니다.

   > 월급날이 25일로 바뀌어서, 엄마한테 매달 20일에 생활비 보내던 걸 26일로 바꾸고 싶어.

3. **AI로 상담 방법 찾기**를 누릅니다. 로딩은 “문의 내용을 확인하고 있어요”로 표시합니다.
4. 별도 **AI 추천 결과** 화면에서 **AI로 해결하기**를 누릅니다. 초기 문의를 다시 전송하지 않고 같은 세션과 받은 답변을 채팅에 표시합니다.
5. **자동이체 메뉴 열기**를 누릅니다. 계좌 간 이체 / 자동납부 탭, 데모 출금계좌, 매월 20일 생활비 내역만 표시합니다. 날짜 수정 입력·확인·변경 완료 화면은 없습니다.
6. **상담으로 돌아가기**로 복귀하면 기존 대화와 요약이 유지됩니다.
7. 같은 상담에서 아래 문장을 전송하면 일반 안내를 제공합니다.

   > 변경 전에 뭘 확인하면 되나요?

최신 응답에 추천이 없으면 추천 없음으로 표시합니다. 과거 추천은 대화 이력으로 유지합니다. 추가 질문에 자동 / 직접 이체를 고르는 이전 단계는 제거했습니다.

### 카드 분실

> 카드 잃어버렸는데 결제 문자가 왔어.

추천 결과 → AI로 해결하기 → 카드 분실 안내 메뉴로 이동합니다. 카드 조회·실제 분실 신고·이용 정지·결제 확인을 실행하지 않습니다. 실제 접수 버튼도 없습니다.

### 오류와 지원 범위

- `/오류`: 요청 오류, 입력 보존, 자동 재전송 없음
- 위 시나리오 외 문장: `UNRESOLVED`, 임의 채널 추천 없음
- 현재 시나리오의 실제 공식 업무 URL을 받지 않아 mock의 출처는 빈 배열입니다. FAQ/지원 도움말은 앱 사용 방법이며 은행 정책 검증 결과가 아닙니다.
- API 모드는 서버가 반환한 검증된 공식 URL만 엽니다. 입력 키워드로 내부 업무 메뉴를 선택하지 않습니다.

## 앱 UI와 상담 상태

- 데스크톱: 최대 440px 앱 화면만 중앙에 표시
- 모바일: 화면 폭과 높이에 맞춘 UI, 내부 스크롤과 고정 입력창
- 홈에서 고객센터 진입 시 세션 생성. 추천 → 채팅 → 업무 메뉴 왕복 시 동일 세션 유지
- FAQ / 안내·지원은 채팅 답변 뒤의 “빠른 도움말도 볼까요?” 버튼을 눌러 확인
- 전화상담·이메일문의 등 채널 선택 버튼은 상단에 고정하지 않음. 추천 결과의 ‘다른 상담 방법’에서 응답에 포함된 채널만 표시
- 대화 숨기기는 삭제 없이 화면만 가림
- 새 상담은 이전 세션 종료 요청 후 새 UUID 세션 생성. 대화·추천·요약·입력·오류를 초기화하고 이전 세션의 늦은 응답은 무시
- 상담 요약 펼치기 / 복사, 실패 시 직접 선택 복사 안내
- 중복 전송·공백 입력 차단, Enter 전송 / Shift+Enter 줄바꿈 / 한국어 IME 조합 중 전송 방지
- 오류 시 입력 보존, 메시지 자동 재전송 없음
- 전송 직후 입력창은 비우고 대기 중 고객 말풍선은 별도 상태로 유지. 실패 시 같은 세션의 전송 원문을 입력창에 복원
- 상담 내용을 localStorage/sessionStorage/IndexedDB에 저장하지 않음
- 화면의 계좌·금융 업무는 모두 데모. 실제 상담 연결·예약·금융거래 없음

## 모드와 프록시

`.env.example`은 현재 저장소에 없습니다. 로컬에서 `.env.local`을 만들고 아래 공개 설정값을 작성합니다. 기존 환경파일에 같은 항목이 있으면 수정하고, 변경 후 서버를 재시작하세요. 실제 환경파일은 Git에서 제외합니다.

```dotenv
VITE_API_MODE=mock
VITE_API_BASE_URL=/api/v1
API_PROXY_TARGET=http://localhost:8080
```

- `VITE_API_MODE`: `mock` 또는 `api`. 기본값 `mock`, 그 외 값은 설정 오류
- `VITE_API_BASE_URL`: HTTP 구현의 공개 기본 경로 (권장 `/api/v1`)
- `API_PROXY_TARGET`: Vite 개발 서버의 `/api` 전달 대상. 경로는 그대로 전달
- API 모드 오류는 mock 성공 응답으로 바꾸지 않음. 클라이언트 요청 타임아웃 90초
- 프록시는 개발 전용. 배포에는 리버스 프록시 또는 합의된 API origin/CORS 설정 필요
- API 키·비밀값을 프론트에 넣지 않음. `VITE_` 값은 브라우저에 공개됨
- 실제 환경변수 파일·`node_modules/`·`dist/`·`.idea/`는 Git 제외

## API 계약 — /api/v1

사용자가 제공한 백엔드 계약에 맞춰 HTTP 계층을 수정했습니다. 백엔드 DTO(`src/types/api.ts`)와 화면용 모델(`src/types/consultation.ts`)을 분리하고 `src/api/adapter.ts`가 변환·검증합니다. 실제 금융거래·상담 연결·예약은 실행하지 않으며, API 모드에서는 서버가 제공한 답변·추천 채널·공식 URL·상담 요약만 표시합니다.

### 상담 시작

`POST /api/v1/consultations` — 요청 본문 없음, 성공 `201`

```json
{ "sessionId": "uuid" }
```

서버는 환영 문구를 반환하지 않으므로 최초 인사말은 프론트의 고정 안내 문구입니다.

### 메시지 전송

`POST /api/v1/consultations/{sessionId}/messages` — 성공 `200`

```json
{ "message": "카드 상담 채널을 추천해줘" }
```

```json
{
  "sessionId": "uuid",
  "answer": "답변",
  "responseType": "CHANNEL_RECOMMENDATION",
  "actions": [{ "menuId": "AUTO_TRANSFER", "label": "자동이체 메뉴 열기", "demo": true }],
  "recommendations": [
    {
      "channel": "CHATBOT",
      "score": 95,
      "processable": true,
      "reasons": ["즉시 처리 가능"],
      "officialPageUrl": "https://spot.wooribank.com/"
    }
  ],
  "consultationSummary": "상담 요약",
  "officialPageUrl": "https://www.wooribank.com/"
}
```

위 URL은 형식 예시입니다. 특정 업무 처리 페이지로 간주하지 않습니다.

화면 변환:

- `answer` → AI 메시지
- `consultationSummary` → 상담 요약과 복사
- `channel` → 채널 식별자. 확인된 `CHATBOT`만 ‘챗봇/채팅상담’으로 표시하고 미확정 ID는 원문 표시
- `score`, `processable`, `reasons` → 서버가 제공한 값 그대로 표시. 점수의 범위·비율·퍼센트를 추측하거나 처리 불가 값을 가능으로 바꾸지 않음
- 추천별 `officialPageUrl` → 해당 채널의 공식 안내 링크
- 최상위 `officialPageUrl` → 공통 공식 안내 링크
- 누락/null인 배열은 `[]`, 누락/null/빈 문자열인 요약·URL은 `null`로 정규화. 필수 문자열·유한 숫자 점수·boolean·요청/응답 세션 일치를 검증

`responseType`은 `FOLLOW_UP` / `GUIDANCE` / `CHANNEL_RECOMMENDATION` / `UNRESOLVED`입니다. 추가 질문은 추천 결과 화면으로 보내지 않고 입력창이 있는 채팅에 표시하며, ‘추천 채널 없음’ 문구를 붙이지 않습니다. 추가 답변 후 추천 상태가 되면 별도 추천 화면을 표시합니다. 문장 키워드로 상태를 추측하지 않습니다. 이전 서버에 필드가 없을 때에만 기존 추천 배열 유무로 추천/일반 안내를 분류합니다.

채팅의 결과 카드는 `CHANNEL_RECOMMENDATION`일 때만 표시합니다. 추가 질문·일반 안내·안내 불가 상태에서는 말풍선과 입력창만 유지하고 ‘이렇게 확인해 보세요’ 카드를 표시하지 않습니다. 실행 중인 백엔드가 이전 빌드라 상태 필드가 누락되면 말풍선은 일반 안내로 표시될 수 있으므로, 새 계약 반영 후 서버를 재시작해야 합니다.

### 상담 종료

`DELETE /api/v1/consultations/{sessionId}` — 요청 본문 없음, 성공 `204 No Content`

204 응답에는 JSON 파싱을 시도하지 않습니다. 새 상담 시 이전 요청을 취소하고 이전 세션의 DELETE를 시도한 뒤 새 세션을 만듭니다. 종료 실패는 별도로 표시하며 새 상담은 독립된 세션으로 생성합니다. 늦게 생성된 이전 세션과 컴포넌트 종료 시 활성 세션도 정리를 시도합니다. 종료 요청 자동 재시도는 하지 않습니다.

브라우저 강제 종료·새로고침·응답 유실 상황에서 DELETE 도착이나 ChatMemory 삭제까지 보장할 수는 없습니다. 서버의 세션 만료/TTL 정책이 필요합니다. 실제 ChatMemory 삭제는 백엔드의 책임이며 프론트 테스트로 검증한 것이 아닙니다.

### 공통 오류

| 상태 | 화면 처리 |
| --- | --- |
| 400 | 입력 확인 안내 |
| 404 | 세션 없음, 새 상담 안내 |
| 409 | 종료된 세션, 새 상담 안내 |
| 502 / 503 | AI·외부 서비스 오류 안내 |
| 500 | 서버 오류 안내 |

백엔드 공통 오류의 code/message를 표시합니다. JSON 본문이 없어도 HTTP 상태를 보존하고 상태별 문구를 표시합니다. 본문에 문자열 `code`/`message`가 있으면 사용합니다. 5xx·연결 실패·90초 타임아웃은 고객이 직접 재시도할 수 있도록 안내하며 자동 전송하지 않습니다. 입력은 보존합니다. 성공 응답의 잘못된 JSON은 연결 실패와 별도 형식 오류로 처리합니다. 실제 API 오류를 mock 성공 응답으로 바꾸지 않습니다.

### 링크와 연동 범위

현재 HTTPS `www.wooribank.com`, `spot.wooribank.com`만 허용하며 사용자정보·비표준 포트를 거부합니다. 다른 도메인은 서버가 반환해도 표시하지 않습니다. 실제 백엔드가 반환할 공식 채널 도메인을 확인한 뒤 허용 목록을 확장해야 합니다. 새 창 링크에는 `noopener noreferrer`를 적용하고 응답 HTML을 실행하지 않습니다.

고정 mock 예시의 메뉴는 `getMockPresentation()`에서 관리합니다. API 모드는 서버가 제공한 `actions`만 사용합니다. `menuId=AUTO_TRANSFER`는 자동이체 목업, `CARD_LOSS`는 카드 분실 안내 목업이며 `demo=true`인 등록된 메뉴만 엽니다. 알 수 없는 메뉴·실제 업무 실행 요청은 열지 않습니다. 이 버튼은 은행 앱 딥링크가 아니며 계좌 조회·날짜 변경·분실신고를 실행하지 않습니다. 추가 질문이나 추천 없는 응답의 액션은 표시하지 않습니다.

### 추가 협의·실서버 검증 항목

- 실제 백엔드 origin, 인증·쿠키·CORS·CSRF 정책
- `CHATBOT` 이외의 채널 enum 전체 목록과 표시명
- `score` 범위/표시 기준, `processable`의 정확한 적용 범위
- 공식 페이지의 도메인 전체 목록과 업무 메뉴/딥링크 연동 방식
- 배포 서버의 명시적 상담 상태와 업무 목업 액션 계약 반영 여부
- 오류 본문 형식, 입력 길이·세션 TTL, 요청 취소와 멱등성
- 실제 배포 환경에서 DELETE 시 대화 삭제 및 종료된 세션의 409 동작

이번 연동 변경은 fetch 응답을 제어하는 계약 테스트와 백엔드의 가짜 모델·세션 테스트로 검증했습니다. 실제 외부 모델을 호출하는 API 통합 시연은 별도 확인이 필요합니다.

## 검증과 한계

타입 검사·ESLint·프로덕션 빌드·자동 테스트 33개로 두 시나리오, 별도 추천 화면, 메시지 중복 전송 방지, 메뉴 왕복과 같은 세션 유지, 새 상담 초기화, 늦은 응답/세션 생성 무시, 오류 입력 보존, IME, 요약 복사, 공식 URL 검증, /api/v1 계약과 공통 오류를 확인합니다.

프론트 개발 서버의 권장 포트는 5173입니다. **8080은 프록시의 백엔드 대상 예시이며 프론트 화면 주소가 아닙니다.** 실제 모드는 로컬 환경 설정에 따라 달라집니다. 새 백엔드 코드를 반영해 서버를 재시작한 뒤 API 모드에서 최초 문의·후속 질문·새 상담을 확인하세요. 서버 메모리의 대화는 재시작하면 초기화됩니다.

브라우저에서 홈 → 문의 → 별도 추천 → AI 채팅 → 자동이체/카드 메뉴 왕복, 요약 클립보드 복사, 오류 입력 보존과 안내 불가를 확인했습니다. 320px·390px 뷰포트에서 가로 넘침이 없음을 확인했습니다. 실제 모바일 기기의 키보드, 모든 한국어 입력기·보조기기 조합은 별도 검증이 필요합니다. 외부 폰트 요청 없이 시스템 글꼴로 표시합니다.

화면 버전은 `feat/chat-ui` 브랜치의 `1b21b61` 커밋으로 업로드했습니다. 이후 API 연동 변경은 `codex/consultation-api-session` 브랜치에서 진행하며 디자인 버전과 분리합니다. 병합은 수행하지 않습니다.



## API 세션 연동 작업

메시지 요청은 여러 AI 도구 호출을 기다리도록 최대 90초 대기합니다. 90초 뒤에는 취소 오류를 표시하고 입력을 보존하며 자동 재전송하지 않습니다. 대기시간 변경이 실제 AI 처리 속도를 개선하거나 서버의 진행 중인 모델 호출을 중단하는 것은 아닙니다.

백엔드는 추천 응답에 processable을 포함하고, 같은 세션의 최근 성공 대화 8회를 서버 메모리에 유지합니다. 후속 질문에서도 정책과 채널은 새로 검증합니다. 프론트의 새 상담은 이전 세션 종료 후 새 세션을 만들며, 종료 요청 성공 시 백엔드 기록도 삭제됩니다. 실제 모델을 이용한 상담 품질·속도와 실행 중인 서버의 반영 여부는 별도 확인이 필요합니다.

### 실제 API 추천 확인용 입력

`policy-demo` 프로필에서 다음 입력은 실제 AI 진단에서 챗봇 → 이메일 → 전화와 `AUTO_TRANSFER` 목업 메뉴를 반환했습니다. 실서비스의 운영 상태를 확인한 결과는 아니며, AI의 조건 해석에 따라 결과가 달라질 수 있습니다.

> 우리은행에서 다른 은행으로 보내는 타행 자동이체 날짜를 매월 20일에서 26일로 바꾸는 방법과 메뉴를 안내해 주세요. 실제 계좌 조회나 변경 실행은 요청하지 않아요. 모바일뱅킹은 이용할 수 있고 아직 변경을 시도하지 않았어요. 긴급하지 않고, 이메일처럼 나중에 답변받는 것도 괜찮으며 실시간 상담은 필요하지 않아요. 채널 선호는 없어요.

이 입력은 가능한 조건을 명시해 추천 흐름을 확인하는 진단 예시입니다. 모든 사용자에게 이 문장을 요구한다는 의미는 아닙니다. 실제 채널 탈락 사유는 백엔드의 도구 진단 테스트로 확인합니다.

같은 입력을 다시 실행했을 때 추가 질문 또는 `REVIEW_REQUIRED` 일반 안내로 끝나는 경우도 확인했습니다. 따라서 현재 실제 AI의 조건 추출과 추천 결과는 재현성이 충분하지 않습니다. 단위 테스트 통과와 한 번의 실제 추천 성공을 안정적인 실서버 동작 보장으로 해석하지 않습니다. 고정된 화면 시연은 mock 예시로 확인할 수 있습니다.
