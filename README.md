# 우리길(WONWAY) 프론트엔드 MVP

고객의 일상 언어로 은행 업무를 안내하는 React + TypeScript + Vite 해커톤 프로토타입입니다. **우리은행 공식 서비스가 아니며, 실제 금융거래·상담 연결·예약은 실행하지 않습니다.**

## 실행

검증 환경: Windows / Node.js 24.20.0 / npm 11.19.0. Node 24 사용을 권장합니다.

```sh
npm ci
npm run dev -- --port 5173
```

실행 주소: http://127.0.0.1:5173/ (포트 사용 중이면 Vite 출력 주소 확인).

```sh
npm run typecheck
npm run lint
npm test
npm run build
```

프로덕션 산출물은 `dist/`에 생성됩니다. 개발 서버는 정식 배포가 아닙니다.

## 화면과 가상 시연

홈 → 고객센터 문의 입력 → **별도 AI 추천 결과** → **AI로 해결하기** → 같은 세션의 채팅 → 업무 메뉴 → 상담 복귀 순서입니다. 왼쪽 설명 영역 없이 앱 화면만 표시합니다. 홈 계좌와 업무 내역은 시연용이며 실제 계좌 API를 호출하지 않습니다.

추천 결과 화면에는 입력한 상황, 추천 채널과 근거, 대화로 이어가는 버튼을 표시합니다. 첫 추천이 CHATBOT이고 processable이 true일 때만 “AI로 해결할 수 있어요”를 표시합니다. 이는 상담 안내를 이어간다는 뜻이며 실제 거래를 실행하지 않습니다. API 응답 순서를 유지하고 임의로 점수를 정렬하거나 순위를 부여하지 않습니다. 가상 시나리오에만 “1순위” 문구를 표시합니다.

현재 두 가상 시나리오는 추천 채널을 각각 하나만 반환합니다. 추천이 여러 개면 첫 항목을 큰 카드로 보여주고, 나머지는 “다른 상담 방법 선택하기”를 펼쳤을 때 응답 순서대로 표시합니다. 나머지 항목에 2·3순위 숫자를 붙이거나 프론트에서 순위를 계산하지는 않습니다.

문의 입력 화면의 빠른 도움말은 기존 박스를 유지합니다. 채팅 화면에서만 답변·업무 안내 뒤에 “빠른 도움말도 볼까요?” 후속 버튼을 표시하며, 누르면 같은 스크롤 영역에서 FAQ / 안내·지원을 펼칩니다. 승인된 컬러 시안에 맞춰 고객 메시지·문의 요약은 연한 회색, AI 말풍선은 하늘색, 추천·업무 카드는 파랑, 카드 안의 이동 버튼은 흰색으로 구분합니다. 입력 시 민감정보 주의사항과 업무 화면 확인 안내는 노란 TIP 영역으로 표시합니다. 파란 배경은 흰 글자의 가독성을 위해 시안보다 약간 어둡게 조정했습니다.

기본 모드는 mock입니다. AI가 실제로 판단하지 않습니다. 아래 예시 버튼은 입력창만 채우며 고객이 전송해야 합니다. 정해진 예시의 공백·문장부호 차이만 허용합니다.

### 자동이체

1. 홈의 **우리길 AI 고객센터**를 누릅니다.
2. **생활비 보내는 날짜 바꾸기** 예시를 입력합니다.

   > 월급날이 25일로 바뀌어서, 엄마한테 매달 20일에 생활비 보내던 걸 26일로 바꾸고 싶어.

3. **AI로 상담 방법 찾기**를 누릅니다. 로딩은 “문의 내용을 확인하고 있어요”로 표시합니다.
4. 별도 **AI 추천 결과** 화면에서 **AI로 해결하기**를 누릅니다. 초기 문의를 다시 전송하지 않고 같은 세션과 받은 답변을 채팅에 표시합니다.
5. **자동이체 메뉴 열기**를 누릅니다. 계좌 간 이체 / 자동납부 탭, 데모 출금계좌, 매월 20일 생활비 내역만 표시합니다. 날짜 수정 입력·확인·변경 완료 화면은 없습니다.
6. **상담으로 돌아가기**로 복귀하면 기존 대화와 요약이 유지됩니다.
7. 같은 상담에서 아래 문장을 전송하면 일반 안내를 제공합니다.

   > 변경 전에 뭘 확인하면 되나요?

최신 응답에 추천이 없으면 추천 없음으로 표시합니다. 과거 추천은 대화 이력으로 유지합니다. 추가 질문에 자동 / 직접 이체를 고르는 이전 단계는 제거했습니다.

### 카드 분실

> 카드 잃어버렸는데 결제 문자가 왔어.

추천 결과 → AI로 해결하기 → 카드 분실 안내 메뉴로 이동합니다. 카드 조회·실제 분실 신고·이용 정지·결제 확인을 실행하지 않습니다. 실제 접수 버튼도 없습니다.

### 오류와 지원 범위

- `/오류`: 요청 오류, 입력 보존, 자동 재전송 없음
- 위 시나리오 외 문장: `UNRESOLVED`, 임의 채널 추천 없음
- 현재 시나리오의 실제 공식 업무 URL을 받지 않아 mock의 출처는 빈 배열입니다. FAQ/지원 도움말은 앱 사용 방법이며 은행 정책 검증 결과가 아닙니다.
- API 모드는 서버가 반환한 검증된 공식 URL만 엽니다. 입력 키워드로 내부 업무 메뉴를 선택하지 않습니다.

## 앱 UI와 상담 상태

- 데스크톱: 최대 440px 앱 화면만 중앙에 표시
- 모바일: 화면 폭과 높이에 맞춘 UI, 내부 스크롤과 고정 입력창
- 홈에서 고객센터 진입 시 세션 생성. 추천 → 채팅 → 업무 메뉴 왕복 시 동일 세션 유지
- FAQ / 안내·지원은 채팅 답변 뒤의 “빠른 도움말도 볼까요?” 버튼을 눌러 확인
- 전화상담·이메일문의 등 채널 선택 버튼은 상단에 고정하지 않음. 추천 결과의 ‘다른 상담 방법’에서 응답에 포함된 채널만 표시
- 대화 숨기기는 삭제 없이 화면만 가림
- 새 상담은 이전 세션 종료 요청 후 새 UUID 세션 생성. 대화·추천·요약·입력·오류를 초기화하고 이전 세션의 늦은 응답은 무시
- 상담 요약 펼치기 / 복사, 실패 시 직접 선택 복사 안내
- 중복 전송·공백 입력 차단, Enter 전송 / Shift+Enter 줄바꿈 / 한국어 IME 조합 중 전송 방지
- 오류 시 입력 보존, 메시지 자동 재전송 없음
- 상담 내용을 localStorage/sessionStorage/IndexedDB에 저장하지 않음
- 화면의 계좌·금융 업무는 모두 데모. 실제 상담 연결·예약·금융거래 없음

## 모드와 프록시

`.env.example`을 `.env.local`로 복사한 뒤 설정합니다. 변경 후 서버를 재시작하세요.

```dotenv
VITE_API_MODE=mock
VITE_API_BASE_URL=/api/v1
API_PROXY_TARGET=http://localhost:8080
```

- `VITE_API_MODE`: `mock` 또는 `api`. 기본값 `mock`, 그 외 값은 설정 오류
- `VITE_API_BASE_URL`: HTTP 구현의 공개 기본 경로 (권장 `/api/v1`)
- `API_PROXY_TARGET`: Vite 개발 서버의 `/api` 전달 대상. 경로는 그대로 전달
- API 모드 오류는 mock 성공 응답으로 바꾸지 않음. 클라이언트 요청 타임아웃 20초
- 프록시는 개발 전용. 배포에는 리버스 프록시 또는 합의된 API origin/CORS 설정 필요
- API 키·비밀값을 프론트에 넣지 않음. `VITE_` 값은 브라우저에 공개됨
- 실제 환경변수 파일·`node_modules/`·`dist/`·`.idea/`는 Git 제외

## API 계약 — /api/v1

사용자가 제공한 백엔드 계약에 맞춰 HTTP 계층을 수정했습니다. 백엔드 DTO(`src/types/api.ts`)와 화면용 모델(`src/types/consultation.ts`)을 분리하고 `src/api/adapter.ts`가 변환·검증합니다. 실제 금융거래·상담 연결·예약은 실행하지 않으며, API 모드에서는 서버가 제공한 답변·추천 채널·공식 URL·상담 요약만 표시합니다.

### 상담 시작

`POST /api/v1/consultations` — 요청 본문 없음, 성공 `201`

```json
{ "sessionId": "uuid" }
```

서버는 환영 문구를 반환하지 않으므로 최초 인사말은 프론트의 고정 안내 문구입니다.

### 메시지 전송

`POST /api/v1/consultations/{sessionId}/messages` — 성공 `200`

```json
{ "message": "카드 상담 채널을 추천해줘" }
```

```json
{
  "sessionId": "uuid",
  "answer": "답변",
  "recommendations": [
    {
      "channel": "CHATBOT",
      "score": 95,
      "processable": true,
      "reasons": ["즉시 처리 가능"],
      "officialPageUrl": "https://spot.wooribank.com/"
    }
  ],
  "consultationSummary": "상담 요약",
  "officialPageUrl": "https://www.wooribank.com/"
}
```

위 URL은 형식 예시입니다. 특정 업무 처리 페이지로 간주하지 않습니다.

화면 변환:

- `answer` → AI 메시지
- `consultationSummary` → 상담 요약과 복사
- `channel` → 채널 식별자. 확인된 `CHATBOT`만 ‘챗봇/채팅상담’으로 표시하고 미확정 ID는 원문 표시
- `score`, `processable`, `reasons` → 서버가 제공한 값 그대로 표시. 점수의 범위·비율·퍼센트를 추측하거나 처리 불가 값을 가능으로 바꾸지 않음
- 추천별 `officialPageUrl` → 해당 채널의 공식 안내 링크
- 최상위 `officialPageUrl` → 공통 공식 안내 링크
- 누락/null인 배열은 `[]`, 누락/null/빈 문자열인 요약·URL은 `null`로 정규화. 필수 문자열·유한 숫자 점수·boolean·요청/응답 세션 일치를 검증

새 계약에는 `responseType`이 없습니다. API 모드는 추천 배열이 있으면 화면 내부에서 추천 결과, 없으면 일반 안내로 분류합니다. 답변 키워드로 추가 질문·안내 불가를 추론하지 않습니다. 화면 모델에는 `FOLLOW_UP`/`UNRESOLVED`가 남아 있고, 현재 mock은 지원하지 않는 입력에 `UNRESOLVED`를 사용합니다. 실제 API에서도 이 구분이 필요하면 백엔드와 명시적인 상태 필드를 협의해야 합니다.

### 상담 종료

`DELETE /api/v1/consultations/{sessionId}` — 요청 본문 없음, 성공 `204 No Content`

204 응답에는 JSON 파싱을 시도하지 않습니다. 새 상담 시 이전 요청을 취소하고 이전 세션의 DELETE를 시도한 뒤 새 세션을 만듭니다. 종료 실패는 별도로 표시하며 새 상담은 독립된 세션으로 생성합니다. 늦게 생성된 이전 세션과 컴포넌트 종료 시 활성 세션도 정리를 시도합니다. 종료 요청 자동 재시도는 하지 않습니다.

브라우저 강제 종료·새로고침·응답 유실 상황에서 DELETE 도착이나 ChatMemory 삭제까지 보장할 수는 없습니다. 서버의 세션 만료/TTL 정책이 필요합니다. 실제 ChatMemory 삭제는 백엔드의 책임이며 프론트 테스트로 검증한 것이 아닙니다.

### 공통 오류

| 상태 | 화면 처리 |
| --- | --- |
| 400 | 입력 확인 안내 |
| 404 | 세션 없음, 새 상담 안내 |
| 409 | 종료된 세션, 새 상담 안내 |
| 502 / 503 | AI·외부 서비스 오류 안내 |
| 500 | 서버 오류 안내 |

공통 오류 본문 스키마는 미정입니다. JSON 본문이 없어도 HTTP 상태를 보존하고 상태별 문구를 표시합니다. 본문에 문자열 `code`/`message`가 있으면 사용합니다. 5xx·연결 실패·20초 타임아웃은 고객이 직접 재시도할 수 있도록 안내하며 자동 전송하지 않습니다. 입력은 보존합니다. 성공 응답의 잘못된 JSON은 연결 실패와 별도 형식 오류로 처리합니다. 실제 API 오류를 mock 성공 응답으로 바꾸지 않습니다.

### 링크와 연동 범위

현재 HTTPS `www.wooribank.com`, `spot.wooribank.com`만 허용하며 사용자정보·비표준 포트를 거부합니다. 다른 도메인은 서버가 반환해도 표시하지 않습니다. 실제 백엔드가 반환할 공식 채널 도메인을 확인한 뒤 허용 목록을 확장해야 합니다. 새 창 링크에는 `noopener noreferrer`를 적용하고 응답 HTML을 실행하지 않습니다.

mock 업무 메뉴 이동은 `getMockPresentation()`에서만 관리합니다. 가상 추천도 `CHATBOT`을 사용하며 로컬 메뉴 정보는 mock 응답에만 별도로 연결합니다. 새 HTTP 계약에 선택지·딥링크·action 필드를 임의로 추가하지 않았습니다. 현재 API 응답만으로는 내부 자동이체 메뉴의 라우팅 경로가 제공되지 않으므로 URL을 임의로 만들지 않습니다.

### 추가 협의·실서버 검증 항목

- 실제 백엔드 origin, 인증·쿠키·CORS·CSRF 정책
- `CHATBOT` 이외의 채널 enum 전체 목록과 표시명
- `score` 범위/표시 기준, `processable`의 정확한 적용 범위
- 공식 페이지의 도메인 전체 목록과 업무 메뉴/딥링크 연동 방식
- 추가 질문·안내 불가의 명시적 상태 필드 필요 여부
- 오류 본문 형식, 입력 길이·세션 TTL, 요청 취소와 멱등성
- 실제 DELETE 시 ChatMemory 삭제 및 종료된 세션의 409 동작

현재 localhost:8080에 실행 중인 백엔드가 확인되지 않아 실서버 API 요청은 아직 검증하지 않았습니다. 검증은 fetch 응답을 제어하는 계약 테스트와 mock UI 흐름을 대상으로 합니다.
